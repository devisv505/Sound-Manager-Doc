## Try the component

The script starts buzzing when Play Mode begins. Move the Bee object from left to right in the Scene view and listen to the change. Change **Wing Speed** in the Inspector, then choose **Stop buzzing**. Choose **Begin buzzing** to start again. Disable the component to check that it cleans up.

This small script does not animate a bee. Move the Transform yourself or attach your own movement script. Keep it within the event's 0.8–4 unit distance range for an easy listening test.

## Position and lifetime

`Following(target, owner)` keeps the sound at a moving Transform. The runtime updates the voice positions as that Transform moves. `At(target.position)` would instead copy one position.

The owner is the hosting GameObject, which can differ from the Bee target. This lets owner-wide cleanup reach the interaction, while the sound follows the right emitter. The supplied Bee event uses owner-loss Stop: losing its required owner or follow target stops the play. See <a href={sitePath('recipes/owner-loss/')}>Stop versus Detach</a> for a different policy.

## Start once, update the value

`BeginBuzzing` ignores repeat starts while the retained handle is alive. Update changes WingSpeed on that play. OnDisable stops it and clears the field. `IsAlive` asks the service whether a play still exists; a nonempty handle alone is not evidence that it is still running.

WingSpeed uses zero smoothing in this graph, so its speed/pitch change is immediate. The <a href={sitePath('recipes/live-parameters/')}>live parameter recipe</a> demonstrates gradual changes instead.
