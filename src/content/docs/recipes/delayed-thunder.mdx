## Try the component

Choose **Start weather**. Raise Rain and Wind and hear them grow gradually. Choose **Strike thunder**: after 0.55 seconds, the rumble begins from Strike Point. Wait more than four seconds before another strike because the event has a cooldown.

For the cancellation test, strike again and immediately choose **Clear weather**, before the 0.55-second delay finishes. The background fades and that waiting rumble should never start. Disable the component to test its final cleanup.

The script does not draw lightning. The marked location inside the Accepted branch is where your own flash effect would start, giving the sound its delayed response. A refused request should not flash as though thunder had been scheduled.

## A fixed position and a shared owner

Weather starts with initial Rain and Wind of zero. Update sends the Inspector targets. Each Thunder request uses `At(strikePoint.position, owner)`: the strike stays at that point even if the cloud moves later.

Both events carry the same owner token. Clear uses `StopOwned(owner, 0.85f)`, which reaches the weather loop and thunder plays, including those waiting inside a graph Delay. Stopping only the Weather handle would leave Thunder independent.

The owner remains valid for another storm from this component. OnDisable stops its owned plays immediately and releases the owner record. The saved Weather event is 2D; Thunder is 3D with a 4–20 unit distance range. Positioning the weather bed itself does not add direction to it.

## Keep the delay in one place

This example sends the thunder request at the moment of the strike. The graph supplies the delay. Adding another C# timer before that request would add a second wait. A separate delayed callback would also need its own cancellation; the graph-owned delay already follows the play's lifetime.
