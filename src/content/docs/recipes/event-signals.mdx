## Try the component

Enter Play Mode and choose **Sound horn** while the engine runs. You should hear a horn over the existing engine sound. Stop the engine, wait for it to end, and try the horn again: a finished play has no running graph to receive the signal. Start the engine to try again.

## Send only when the action happens

The complete component retains the accepted Engine handle, checks it is alive, and sends the exact authored signal name:

```csharp title="Signal call inside SoundHorn · excerpt"
SoundBus.SendSignal(engine, "Horn");
```

The graph's On Signal node named Horn responds by starting its horn voice. The engine loops continue. Calling Play with Sounds.Engine for every horn press would create or replace entire engine plays instead.

Use the graph's exact signal spelling. For the Engine graph, `"Shift"` is another authored signal. A signal does not imply a universal engine command: a different graph responds only to the signals it defines.

## Signals are different from notifications

A **signal** travels from your code into a graph: “sound the horn.” A **notification** travels from the runtime back to your code: “this play finished or was cancelled.” The component subscribes once, matches its own handle, clears it on a terminal notification, and disposes the subscription on disable.

Workshop uses the same mechanism for Work, Pause, and Strike. Set Tool first, then send Work. Its graph signal named Pause stops tool voices; it is not the runtime's pause function.
