## Local pause belongs to all related handles

```csharp title="Inside TwoTrackMusic.SetPaused · excerpt"
SoundBus.SetPaused(current, value);
SoundBus.SetPaused(outgoing, value);
```

`value` is true to pause and false to resume. Pausing only the current play would leave the outgoing song audible or advancing. Pausing is not stopping: it keeps the play, voices, and graph progression available for continuation. The component also avoids discarding the outgoing handle during pause.

The complete component below can be used directly. Stop music now ends both plays and clears the local pause flag; disabling the component performs the same cleanup.

## Global pause, as used by Launch

Launch pauses the service as a whole so its pad, countdown, and rocket audio stay together. It also pauses its own animations and particles. Those visual effects are outside Sound Manager.

The following excerpt belongs in a controller that owns the pause interaction and restores the previous state when it leaves. Keep `wasPaused` and `service` as fields if pause and restoration happen in separate methods:

```csharp title="Service-wide pause and restoration · excerpt"
var service = SoundServices.Current;
if (service != null)
{
    bool wasPaused = service.Paused;
    service.Paused = true;
    // Keep it paused while your interaction needs it.
    // On exit, restore the state you found:
    service.Paused = wasPaused;
}
```

This block demonstrates the state ownership; running it as-is restores immediately. Do not blindly set Paused to false on exit if another system had already paused it. A per-play resume does not override a paused service. LaunchUI is explicitly configured to ignore game pause, allowing UI clicks to remain audible.

Read <a href={sitePath('demos/10-launch/')}>Launch's full walkthrough</a> for its combined pause behavior. Workshop's signal named Pause is a third, different concept: that graph stops tools and stays alive waiting for Work.
