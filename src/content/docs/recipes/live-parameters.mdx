## Try the component

The engine starts when Play Mode begins. Slowly move **Rpm** from 0 to 1, then drop it to 0. Listen as it climbs and settles. Use **Sound horn** to add a response without replacing the engine. Use **Stop engine** to hear its ending, then **Start engine** to repeat. Disable the component to test cleanup.

This recipe sets Load to 0.2 at start and changes only Rpm live. The full Engine demo computes both from its vehicle controls.

## Target and current value

The graph declares Rpm from 0 to 1, with rise rate 0.8 and fall rate 1.5 **units per second**. An initial context override becomes the starting value. Later `SetFloat` calls change the target, and the graph's current value moves toward it. Repeatedly setting the same target does not restart the play or reset the smoothing.

The graph maps that current value into playback speeds and layer volumes. To display what the audio is currently using, read the parameter state:

```csharp title="Inside a component with a retained engine handle · excerpt"
var service = SoundServices.Current;
if (service != null &&
    service.TryGetParameter(engine, SoundParameters.Engine.Rpm, out var rpmState))
{
    float audibleRpm = rpmState.Current.number;
    float requestedRpm = rpmState.Target.number;
}
```

The variables above are normalized values. Apply your own display conversion if you want an RPM dial.

## The same idea for weather

Rain and Wind use the same target/current pattern to blend ambience. Rain rises at 0.35 and falls at 0.5; Wind uses 0.25 and 0.4. The <a href={sitePath('recipes/delayed-thunder/')}>StormSounds component</a> starts them at zero, updates targets, and cleans up the entire storm by owner.

Float smoothing is part of the parameter definition. A rate of 0 means immediate change, not a zero-second fade command. Int, Bool, and Asset parameters choose values directly instead of smoothly moving through them.
