## Unity example verification

The exact `examples/CampfireSound.cs` was compiled in memory with the runtime harness in `VerifyCampfireExample.cs.txt`. The harness executed in the running Campfire scene and passed eight checks:

- Initial play accepted and retained a live handle.
- Repeated Ignite did not create another instance.
- Ignition finished and one crackle voice remained looping.
- Generated Intensity parameter accepted a live update.
- Per-play pause and resume succeeded.
- Extinguish cleared the component's handle while release playback remained alive.
- Release completed and the previous handle stopped being alive.
- Disabling the component cleaned up its second play and completed its release.

See `campfire-example.json` for the example hash, result, timing, notifications, and compiler diagnostics. The harness reported two Unity deprecation warnings for its `FindFirstObjectByType` lookup calls; neither warning comes from the published example component. No compilation error or failed runtime check occurred. The complete example is imported directly into its page, so validation and displayed code use the same source file. The shorter reference snippets are labeled excerpts and were checked against the source contracts; they are not claimed as standalone compiled components.

A relevant source correction is documented: Campfire's On Stop flow explicitly stops its ignition/crackle nodes, applying their authored 0.3/0.6-second fade-outs. The API's requested 0.15-second fade is a fallback for remaining existing voices, not an override of those node Stop paths.
